# Diretrizes de Engenharia e Registro de Bugs (3EATCRU OS)

Este documento serve como histórico de arquitetura e bugs resolvidos. Use os scripts npm definidos em package.json para lint, testes e build; resultados antigos neste arquivo não comprovam o estado atual.

---

## 1. Princípios e Regras Fundamentais

1. **Código Pequeno e Modular:**
   - Nenhum componente ou arquivo deve ser inflado ou concentrar responsabilidades excessivas.
   - Decomposição estrita em subcomponentes atômicos (modais, tabelas, cabeçalhos, formulários de subdomínio).
   - Componentes no padrão Angular standalone com `ChangeDetectionStrategy.OnPush` e signals para reatividade leve.

2. **Entenda Antes de Modificar:**
   - Mapear dependências antes de qualquer alteração (`EcosystemService`, roteamento, signals reativos).
   - Não remover métodos ou propriedades em uso por janelas do SO ou módulos de PDV/KDS sem conferir as referências.

3. **Capacidade Máxima e Simplicidade:**
   - Evitar sobre-engenharia ou abstrações desnecessárias.
   - Design visual limpo, moderno e responsivo com Tailwind CSS v4 e ícones Material Icons.

4. **Testes e Verificação Obrigatória:**
   - Todo fluxo alterado deve ser validado via compilação (`compile_applet`), tipagem (`tsc --noEmit`), lint (`bun run lint`) e testes unitários (`bun run test:ci`).

5. **Ecosistema Bun:**
   - Utilizar scripts gerenciados via Bun para agilidade no ciclo de feedback:
     - `bun run check`: Executa lint completo e bateria de testes automatizados (`vitest`).
     - `bun run test:ci`: Executa suite de testes unitários sem watch.
     - `bun run lint`: Executa análise estática de código com ESLint Angular 21.
     - `bun run build`: Compilação de produção com otimização AOT zoneless.
